# Bitbucket

This section is focused on understanding Bitbucket as a Git hosting platform, especially after learning Git and GitHub.

## Why Bitbucket?

**Git** = version control system

**GitHub / Bitbucket** = platforms that host Git repositories

Once you understand Git + GitHub, Bitbucket becomes relatively easy because the core workflow is almost the same.

## Important note

Don't learn GitHub and Bitbucket deeply at the same time. Learn Git properly first, then GitHub, then spend a small amount of time understanding how Bitbucket differs.

## Core learning rule
For every Bitbucket workflow step, understand:
- What is it?
- Why do I need it?
- What does it change?
- How do I verify it?

Example:

```bash
git push
```

Don't only memorize it. Understand:

> `git` → the version control tool  
> `push` → uploads your commits to the remote repository  
> The remote repository could be GitHub or Bitbucket
